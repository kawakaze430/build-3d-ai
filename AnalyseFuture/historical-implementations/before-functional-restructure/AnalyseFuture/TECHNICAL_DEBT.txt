This list distinguishes current gaps from completed recovery work. It builds
on existing implementations; it is not permission to rebuild the product,
start paid compute, or activate preserved upstream code. Responsible roles are
work owners to assign, not a claim that those people are already staffed.
See FEATURE_INVENTORY.txt for implemented feature ownership and
TEST_AND_VALIDATION_REPORT.txt for executed checks and their limits.

COMPLETED IN THE CURRENT CONSOLIDATION

- Shared streamed request-body enforcement replaces the product route's
  post-allocation size check and the login route's unbounded JSON read. Limits
  are 12 MiB for product POST and 8 KiB for session POST. Fourteen web unit tests
  passed, including ten new boundary/error cases, and TypeScript passed.
- The studio reuses the existing artifactDownloadUrl helper rather than a second
  handwritten download path. This is one URL responsibility, not a new API.
- Gateway Docker/Compose and gateway CI now use the same CPU requirements.lock
  constraints as product packaging. Original packaging remains preserved.
- All four root workflows explicitly request contents: read. This addresses
  inherited-default ambiguity; artifact/hash pinning remains separate debt.
- Historical feature review preserves later worker/storage/download safety
  behavior rather than restoring inferior older versions. The recovered pip
  resolution auditor is separate from real wheel-byte and model approval.

The exact active changes and original copies are recorded in
CONSOLIDATION_REPORT.txt and ORIGINAL_TO_NEW_PATH_MAPPING.txt. Do not relist
these completed items as entirely missing work.

PRIORITY DEFINITIONS

P0: must resolve before the dependent milestone can honestly be claimed.
P1: concrete engineering gap to close before wider exposure or meaningful scale.
P2: improve maintainability, coverage and user completeness after the narrow
    workflow has a measured acceptance baseline.
P3: optional research; pursue only when rights, value, data and resources justify it.

The order below follows dependencies, not an invented delivery schedule.

P0-01. COMPLETE EXACT MODEL/RUNTIME QUALIFICATION
Owner: ML/inference engineer with release/licensing reviewer and project owner.
Evidence:
  services/generation/triposr_candidate/, runtime_manifest.json,
  docs/FIRST_REAL_GPU_RUNBOOK.md, and the empty default approved_models list.
  CPU preparation and provenance helpers exist; they are not real inference.
Work:
  Complete independent Python/native/CUDA/OS artifact hashes and notices;
  inspect the candidate runtime; establish trusted checkpoint/local config
  loading and headless texture-baking compatibility. Resolve or explicitly
  qualify source-archive build artifacts such as antlr4-python3-runtime rather
  than treating index metadata as verified wheel bytes.
Acceptance:
  Exact reviewed runtime/weights/data decision, reproducible artifact evidence,
  qualified preparation boundary, and a documented experiment with an approved
  bounded resource budget. Only then attempt genuine image-to-textured-GLB,
  private product download, browser view and Blender import with recorded
  failures, VRAM, timing and actual cost. No approval is inferred here.

P0-02. KEEP QUALIFIED INPUT AND PREPARED SOURCE CONTEXT CLOSED
Owner: ML/runtime security engineer.
Evidence:
  prepare_runtime.py verifies the source commit and selected changed blobs, but
  copies a working directory whose ignored files are not covered by ordinary
  clean Git status. Historical source snapshots also omit their submodules.
Work:
  Use a fresh exact upstream checkout now. Before production, export only
  explicitly reviewed tracked content or reject unexpected ignored additions;
  inventory the complete prepared build context and every downloaded artifact.
Acceptance:
  A safe fixture with an extra ignored file cannot silently enter the prepared
  context. Commit/blob mismatch and unexpected download attempts fail closed.
  The check must not execute a planted script or require live model inference.

P0-03. FINISH PUBLIC IDENTITY AND OPERATING LIFECYCLE BEFORE PUBLIC RELEASE
Owner: product/backend/security leads.
Evidence:
  Private user keys, immutable external identity mapping and optional disabled
  JWT/JWKS verification already exist. Public signup/recovery/deletion,
  production sessions, retention/deletion and support operations are incomplete.
Work:
  Integrate a reviewed identity lifecycle and trusted browser-to-API assertion
  path, define account deletion/asset retention, audit destructive operations,

Acceptance:
  Owner/tenant isolation, verification/recovery/logout/deletion, abuse limits,
  restore checks and billing failure cases pass in a supported deployment.
  Existing storage/active-job limits must not be presented as a cash budget.

P0-04. RESOLVE EXTERNAL ACCOUNT/RULE EVIDENCE WHEN COMPROMISE IS REPORTED
Owner: repository/account owner or authorized organization administrator.
Evidence:

P1-01. DEFINE GLB EXTENSION AND DECODED-RESOURCE BUDGETS
Owner: graphics/security engineer.
Evidence:
  inspect_glb provides bounded structural/checksum preflight, while ModelViewer
  uses Three/R3F/drei parsing. Full accessor validity, extensions, decompressed
  geometry/texture resources and decoder behavior are not comprehensively gated.
Work:
  Define supported glTF extensions, decoded asset complexity, external decoder
  policy and error behavior; add adversarial fixtures and isolated downstream
  parser/import checks. Keep technical integrity distinct from visual quality.
Acceptance:
  A bounded on-disk file cannot obtain a success label while exceeding the
  declared decoded-resource policy. Real supported artifacts import/render;
  known unsupported variants fail clearly. No arbitrary 3D script is executed.

P1-02. ADD PREPARSE BOUNDS TO THE PRIVATE OPERATOR GATEWAY IF EXPOSURE EXPANDS
Owner: backend/security engineer.
Evidence:
  apps/gateway/src/build3d_gateway/main.py applies signature and size checks
  after multipart spooling. The tenant API already has earlier ASGI body limits
  and Pillow normalization; the two responsibilities should not be conflated.
Work:
  Keep the gateway private and authenticated. Add a preparse/perimeter byte
  bound and request/resource limits before expanding caller access.
Acceptance:
  Declared and unknown-length oversized inputs are rejected without consuming
  unbounded temporary storage/memory; valid supported images still follow the
  approved upstream contract. The new web body reader does not fix this layer.

P1-03. BOUND FILESYSTEM INVENTORY DISCOVERY, NOT ONLY ITS REPORT
Owner: storage engineer.
Evidence:
  storage.py gathers candidates via list/rglob before enforcing returned object
  count. maintenance.py reports fail-closed truncation, but discovery memory
  can grow first. Inventory metadata comparison is not a complete byte audit.
Work:
  Use a deterministic streaming traversal that stops at the documented limit.
  Design a separate optional bounded full-content verification if required.
Acceptance:
  Large controlled directory fixtures demonstrate bounded traversal/reporting,
  preserved owner/path checks, clear truncation, and no accidental deletion.
  Keep scanner operation read-only and copy-only migration semantics intact.

P1-04. FIX THE POLLING ABORT-CONTROLLER CAPTURE RACE
Owner: frontend engineer.
Evidence:
  Studio's timer aborts and replaces a mutable controller. An earlier run's
  catch can inspect the replacement signal and misreport an intentional abort
  as a service failure when a request takes longer than the five-second interval.
Work:
  Capture a controller/signal per run and check that same signal on completion
  or failure. Preserve project-switch/unmount cancellation and avoid stale state.
Acceptance:
  A delayed mocked response aborted by the next poll does not create a false
  global 503 alert; a genuine new request failure still appears. A project
  switch cannot apply an earlier project's completion to the new selection.

P1-05. ADD REAL UI PAGINATION FOR PROJECTS AND PERSISTED JOBS
Owner: frontend/product engineer.
Evidence:
  api.ts queries limit=100,offset=0; Studio exposes no pagination. The backend
  already supports bounded limit/offset. Persistence is not the same as showing
  every record in the current UI.
Work:
  Reuse the existing API paging contract; add stable ordering, page controls or
  an explicit supported load-more experience, and preserve selected project/job.
Acceptance:
  More than 100 controlled records remain reachable without cross-owner data
  exposure or duplicate/missing pagination results. Correct documentation that
  implies unlimited/full history display until the interface passes that gate.

P1-06. FINISH ARTIFACT/BUILD INTEGRITY AND RUNTIME TRUST CONFIGURATION
Owner: release/build and security engineers.
Evidence:
  CPU requirements.lock constrains releases but lacks independent artifact
  hashes; web dev requirements include ranges with no committed npm lock;
  base images/actions use mutable tags. Candidate index reports are metadata.
  Two initial CPU builds failed missing trusted CA; secret-mounted trusted
  host CA corrected both builds without baking the certificate or disabling TLS.
Work:
  Design reviewed immutable dependency/action/image updates and notice/SBOM
  evidence. Preserve verification during package installation. Define approved
  runtime trust for managed/private CAs separately from the build-only mount.
Acceptance:
  Reproduction uses known artifacts and fails on unexpected hash/signature or
  trust changes. Runtime HTTPS to intended upstream/JWKS/S3 destinations works
  with an approved trust configuration. No TLS=false, ignored certificate error
  or copied private CA material in a public image/report is used to pass checks.

P2-01. TEST THE REAL BACKEND/BROWSER CONTRACT BEYOND SYNTHETIC FIXTURES
Owner: QA/full-stack engineer.
Evidence:
  Existing browser tests intentionally use a local synthetic API and triangle
  GLB. Web parser helpers and BFF allowlist have useful but incomplete direct
  adversarial coverage. The status isPollable utility is not used by Studio's
  actual interval loop, so its unit tests do not establish polling behavior.
Work:
  Add a bounded real-API browser acceptance route and explicit malformed data,
  route/query/body/timeout tests where they protect supported behavior. Retain
  fast synthetic tests and label them accurately rather than replacing them.
Acceptance:
  Login/project/history/quota/verified download paths run against the intended
  backend in a clean isolated fixture. New tests fail when their actual trust
  boundary breaks, not merely repeat implementation lines.

P2-02. MAINTAIN COHERENT PACKAGE/DEPLOYMENT BOUNDARIES

P2-04. KEEP STORAGE RETENTION AND DESTRUCTIVE LIFECYCLE EXPLICIT
