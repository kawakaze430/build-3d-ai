IMPORTANT LEGAL AND TECHNICAL BOUNDARY
- A public GitHub repo is NOT a commercial use grant. GitHub's license metadata below is only a discovery hint.
- Audit exact source commit, LICENSE/NOTICE, pretrained weights, training data, dependencies, SaaS and geography/territory terms, model cards and distribution obligations.
- Do not vendor a whole AI project or deploy any stock checkpoint because it appears here. Use isolated, version-pinned adapters only after engineering/legal review.
- Do not infer model quality, GPU speeds, GLB validity, texture quality or Blender rig correctness from stars, websites or mock CI.
- GH-license=NOASSERTION or UNKNOWN means GitHub metadata did not confirm an SPDX ID, NOT that unrestricted reuse is allowed.
- Last-push is repository metadata for triage (not a guarantee of maintenance, quality or compatibility). ARCHIVED means GitHub marks it read-only.
- 'Already used' denotes code/tools in the CPU/web product baseline, NOT proof of paid GPU inference or commercial launch.

RECOMMENDED STUDY SEQUENCE FOR THIS PROJECT
1. First real GPU result: TripoSR + its guarded scikit-image patch + xatlas-python + our embedded-GLB packager and validator; pursue only after exact budget/legal clearance.
2. Geometry/export: Khronos glTF-Validator, glTF-Transform, xatlas, trimesh, meshoptimizer and Blender import tests.
3. Production character workflow: UniRig, SkinTokens, Puppeteer, Blender shape keys/Rigify, facial tracking and lip-sync references.
4. Later quality benchmarks: TRELLIS.2, TRELLIS, InstantMesh, SF3D/SPAR3D, Hunyuan3D, Step1X, TripoSG; blocked stock paths must stay blocked.
5. Editability/world mode: BlenderProc, Infinigen, OpenUSD, WorldGen; keep Gaussian splats distinct from polygon scene graphs.
6. Commercial product: preserve existing FastAPI/Next.js/Three.js code and extend identity, durable jobs, private storage, security, observability and paid deployment only through approved gates.

REQUIRED NEXT STEPS BEFORE IMPLEMENTING ANY NEW ENTRY
1. Select a single feature and compare 2-3 candidate repositories to the implementation already merged in main.
2. Pin an exact commit and inspect source, README, LICENSE, NOTICE, model cards/weight hashes and transitive CUDA/graphics dependencies.
3. Write findings in docs/REUSE_AUDIT.md and docs/LICENSE_MATRIX.md. Use NEEDS_PERMISSION/REJECTED if uncertain or restricted.
4. Test in an isolated service with real model artifacts; record correctness, VRAM, latency, CPU/GPU cost, failure modes, mesh/UV/material/animation quality and Blender compatibility.
5. Add a narrow reviewed PR with CI, security controls, rollback and an evidence-backed Go/No-Go decision.
6. Never start billable GPU/cloud work or training without explicit budget/account/license approval.
