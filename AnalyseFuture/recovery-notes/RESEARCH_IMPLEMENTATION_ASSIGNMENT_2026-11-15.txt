**Primary Repository 1: Application, pipeline or integration foundation**

A mature project that provides substantial value in orchestration, model serving, asset processing or multi-stage 3D workflows.

**Primary Repository 2: AI generation or production-critical capability**

A mature implementation providing an essential capability such as image-to-3D generation, text-to-3D generation or another proven critical component.

This pairing is a hypothesis, not a rigid rule.

If research demonstrates that another combination is substantially better, select that combination and justify it.

Your selection must optimize for the complete project, while giving special weight to achieving the first verified real GPU generation.

## Selection criteria

Evaluate the finalists using a weighted scorecard.

Suggested weights:

| Criterion | Weight |
|---|---:|
| Fit with existing Build 3D AI architecture | 20% |
| Actual capability and output quality | 20% |
| Commercial licensing and deployment feasibility | 20% |
| Engineering maturity and maintenance | 15% |
| GPU requirements and operating cost | 10% |
| Integration complexity | 10% |
| Extensibility and future development | 5% |

A confirmed commercial-license incompatibility must disqualify the affected deployment path regardless of its numerical score.

Do not confuse source-code licensing with model-weight licensing.

A repository can have an MIT or Apache license while its pretrained weights, datasets or runtime dependencies impose different restrictions.

Investigate all relevant licensing layers:

1. Source code
2. Model weights
3. Training datasets
4. Runtime dependencies
5. Rendering dependencies
6. SaaS hosting restrictions
7. Commercial-use terms
8. Geographic restrictions
9. Attribution and redistribution requirements

Consult the existing license audit.

In particular, recheck the previously documented concerns about Step1X-3D, TRELLIS.2, TripoSG and Hunyuan-derived components.

Do not silently approve something the existing project has explicitly blocked.
